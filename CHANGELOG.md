# История изменений

## 2026-11-03

### События от самих камер

Сервер научился принимать бортовую детекцию камер и публиковать её в ту же
шину, что и собственную детекцию `ai-detector`. Отдельная ветка обработки не
нужна: события сразу попадают в журнал, архив, уведомления, вебхуки и поток
тревог.

- **OpenIPC (Majestic)** — WebSocket `/ws/analytics`. Классы: человек, машина,
  лицо (приводится к человеку), животное. Координаты рамок переводятся из
  пикселей кадра в доли.
- **Hikvision** — фирменный `/ISAPI/Event/notification/alertStream` с HTTP
  Digest (ONVIF-события на живых камерах отвечают `NotAuthorized`). Поддержаны
  VMD, пересечение линии, вторжение в область и tamper. Класс берётся из
  `detectionTarget`: `human` → `person`, `vehicle` → `car`; без цели событие
  публикуется как `motion`, чтобы не поднимать ложную тревогу о человеке.
- **ONVIF** — PullPoint-подписка: `MotionAlarm`, `CellMotionDetector/Motion` и
  события с классом объекта.
- Повторы одного класса с одного места склеиваются за `min_interval_sec`
  (по умолчанию 10 секунд): камера присылает детекцию несколько раз в секунду.

Настройка — в карточке камеры, вкладка камерных событий. API:
`GET/PUT /api/v1/cameras/{id}/camera-events`. По умолчанию приём выключен,
иначе на каждый объект приходило бы два события — от камеры и от нашего
детектора. Источник выбирается автоматически (`source: auto`) либо
принудительно: `onvif`, `hikvision`, `openipc`.

Важно: Smart-события Hikvision и объектная детекция OpenIPC должны быть
включены на самой камере. Сервер их не включает — это изменение конфигурации
устройства. Для объектной детекции OpenIPC нужна установленная NPU-модель и
принятая EULA в веб-интерфейсе камеры; до этого приходят только события
движения.

### Мобильное приложение

- **Фильтры архива.** Сужение списка по камере, причине записи (объект,
  пересечение линии, лицо, номер, СКУД, ручная и непрерывная запись) и поиск
  по номеру машины, имени человека или классу объекта. Фильтры применяются на
  сервере (`GET /recordings?trigger=...&search=...`), поэтому ищут по всему
  архиву, а не только по загруженной странице.
- **Откат на дополнительный поток.** Если основной поток не поднялся ни по
  WebRTC, ни по HLS, приложение автоматически открывает субпоток и показывает
  причину. Частая причина — лимит RTSP-сессий камеры
  (`453 Live memory budget is full`).
- Плеер сбрасывает счётчик повторов при смене камеры или потока и сообщает о
  неудаче вместо бесконечных попыток.

### Стабильность сервера

- Контейнерам заданы пределы памяти: `postgres` — 1 ГБ, `go2rtc` — 1 ГБ,
  `backend` — 4 ГБ, `ai-detector` — 5 ГБ, `frame-publisher` — 2 ГБ. Утечка
  теперь убивает процесс внутри контейнера, а не всю систему в global OOM.
- Буфер непрерывной записи и пребуфера событий перенесён с системного диска
  (`/var/lib/nvr`) на группу дисков `/nvr/video`: `RECORD_BUFFER_DIR`,
  `AUDIO_CLIP_DIR`. Раньше пятиминутные фрагменты архива заполняли корень.
- Ширина кадра номеров из основного потока по умолчанию `1280` вместо `0`:
  на 2K/4K-камерах декодирование полного кадра разрасталось до гигабайтов.
- Публикатор кадров и запись берут потоки из внутреннего RTSP go2rtc, а не
  подключаются к камерам напрямую. Это снимает исчерпание RTSP-сессий OpenIPC
  (`453 Live memory budget is full`) и ускоряет открытие живого просмотра.
- HLS отдаёт `index.m3u8` только после появления реального плейлиста: пустой
  ответ больше не выглядит как успешный, при таймауте возвращается 504.

### Сканер камер

- Исправлено мусорное значение прошивки `" sub:"`: пустое разрешение в конфиге
  Majestic больше не добавляется в список частей.
- В документации описано, что для OpenIPC нужно указывать логин и пароль
  камеры: без них `/api/v1/config.json` отвечает 401, и вендор не определяется.
  Камеру, добавленную вручную без сканирования, система не опрашивает
  автоматически — вендор и адреса потоков нужно заполнить в карточке.
